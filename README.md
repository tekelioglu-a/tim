# Peer-verified messaging prototype

Stage 5: TLS 1.3, server-side Ed25519 challenge authentication, and client-side Ed25519 verification of each received message.

## Build

```sh
gcc -Wall -Wextra -Wpedantic -O2 -pthread server.c -o server -lssl -lcrypto
gcc -Wall -Wextra -Wpedantic -O2 client.c -o client -lssl -lcrypto
```

## Generate test keys

```sh
chmod +x make-certs.sh make-identities.sh
./make-certs.sh
./make-identities.sh
```

Do not overwrite previously trusted identity keys unless you intend to rotate them and redistribute their new public keys securely.

## Run

```sh
./server server.crt server.key alice.pub bob.pub
./client localhost alice alice.key ca.crt alice.pub bob.pub
./client localhost bob bob.key ca.crt alice.pub bob.pub
```

Client input: `bob Hello Bob!`

Expected recipient output: `[VERIFIED alice] 2026-...Z Hello Bob!`

## Protocol

`MSG recipient timestamp signature_hex plaintext`

`FROM sender timestamp signature_hex plaintext`

Ed25519 signature covers a domain-separated length-prefixed transcript containing `messenger-msg-v1`, sender, recipient, timestamp, and plaintext. Server does not sign on behalf of clients. Client checks signature using a locally provisioned public key. These public keys must be exchanged and verified through an authenticated channel independently of the server; copying them from a malicious server defeats the objective.

## Security limitations

* Development prototype, not production ready.
* Message content remains visible to the server; no end-to-end encryption yet.
* No anti-replay mechanism, durable message storage, identity key rotation, or secure public-key discovery.
* Messages are not encrypted or authenticated independently of TLS against traffic analysis.
* Signing keys must remain private. Key files and certificates generated by scripts are for local development.
* `SENT` means enqueued for an online recipient, not verified or read.
* Server's TLS handshake is blocking without an explicit timeout. Hardening is required before Internet deployment.
* Newline-delimited framing: messages cannot contain literal newlines.
